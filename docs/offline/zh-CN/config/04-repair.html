维修模块

运行时目录：

Data/F4SE/Plugins/ConditionSystemFramework/Repair/

维修模块分为三个子模块：

Repair/JuryRigging/   混修：决定供体能否修理目标
Repair/OverRepair/    过量维修：决定修理上限
Repair/RepairKits/    修理包：决定修理包能修什么以及修多少

维修资格、维修上限和修理包强度是三个独立问题，不要把 DisplaySkill、RequiredSkill 和 MCM 上限混为一个条件。

Provider 选择

Repair 的 Provider 是单选式。文件必须满足：

  1. 根对象有 RequiredPlugin。
  2. 文件名必须严格等于 <RequiredPlugin>.json，不区分大小写。
  3. RequiredPlugin 必须已加载。
  4. 同一目录中多个候选文件按 Repair/ProviderSelection.json 选择。

当前选择策略：

| 子模块 | 当前模式 | |---|---| | JuryRigging | JsonPriorityFirst：先比较 ProviderPriority，再比较插件加载顺序 | | OverRepair | PluginLoadOrderFirst：先比较插件加载顺序，再比较 ProviderPriority | | RepairKits | 读取 0_DefaultKits.json 模板，不使用技能 Provider 选择 |

Fallout4.esm.json、Classic Skill System.esp.json、StandaloneRepair.esp.json 和 You Are Exceptional.esp.json 是互相独立的 Provider 候选，不会合并成一套规则。

RequiredSkill

维修规则使用以下结构：

{
  "Type": "AV",
  "Plugin": "Classic Skill System.esp",
  "FormID": "0xFA0",
  "MinRank": 1.0,
  "ScaleFactor": 1.0
}

Type 支持：

  • AV：读取 Actor Value。
  • Perk：读取玩家 Perk Rank。
  • Global：读取 Global 数值。

也可以使用 EditorID。MinRank 对有些规则表示最低技能/等级门槛；ScaleFactor 先乘在读取值上，再参与阈值比较。插件或 FormID 解析失败时，规则不会授予维修权限。

Jury Rigging

Provider 外层

{
  "RequiredPlugin": "Classic Skill System.esp",
  "schemaVersion": 3,
  "module": "Repair.JuryRigging",
  "ProviderPriority": 100,
  "DisplaySkill": { "Type": "AV", "Plugin": "Classic Skill System.esp", "FormID": "0xFA0" },
  "RepairEfficiency": { "Type": "FNV", "Skill": { "Type": "AV", "Plugin": "Classic Skill System.esp", "FormID": "0xFA0" } },
  "JuryRiggingRules": []
}

DisplaySkill

DisplaySkill 只控制混修界面右上角显示的技能值。它不会：

  • 授予跨类别维修资格。
  • 改变 RequiredSkill。
  • 改变工作台界面。

因此可以让页面显示 Repair 技能，同时把真正的跨类别权限交给 RequiredSkill 或游戏 Perk 条件。

RepairEfficiency

当前只接受 Type: "FNV"。启用后，CSF 按以下逻辑计算混修增加量：

better       = max(targetCondition, materialCondition)
lower        = min(targetCondition, materialCondition)
combined     = better
             + lower * LowerConditionMultiplier
             + BaseBonus
             + RepairSkill * SkillMultiplier
rawAddition  = max(0, combined - targetCondition)
finalAddition = rawAddition * JuryRuleEfficiency

当前 Classic Skill System Provider 的默认值是：

BaseBonus                 = 0.05
LowerConditionMultiplier  = 0.05
SkillMultiplier            = 0.0015

最后的 JuryRuleEfficiency 来自规则自身的 MaterialConditionMultiplier，再乘 EfficiencyModifiers。这让 Repair 技能同时影响“能否混修”和“混修能修多少”，而不是只显示在 UI 上。

JuryRiggingRules

每条规则至少需要：

{
  "RuleName": "Same Family Repair",
  "Priority": 100,
  "MaterialConditionMultiplier": 0.8,
  "AppliesTo": {
    "target": { "all": ["weapon"] },
    "material": { "all": ["weapon"] }
  },
  "Compatibility": {
    "all": [{ "type": "sameGroup", "group": "Weapon.Handling" }]
  }
}

AppliesTo.target 和 AppliesTo.material 分别检查目标物品和供体物品。谓词字段含义：

  • all：必须全部拥有。
  • any：至少拥有一个。
  • none：不能拥有任何一个。

常用排除写法：

"none": ["Weapon.Flag.Ignore"]

Compatibility 类型

| 类型 | 条件 | |---|---| | always | 不追加类别关系条件；仍需通过 target/material 谓词 | | sameBase | 两件物品的基础 FormID 相同 | | sameGroup | 两件物品在指定互斥分类组中选择了相同类别；缺少类别时失败 | | sameOptionalGroup | 两件物品都缺少该组，或都命中且类别相同；一件有、一件没有时失败 | | sharesAnyCategory | 两件物品在指定组前缀下至少共享一个类别 | | groupPair | 目标类别和供体类别必须落在 pairs 中；symmetric: true 时也接受反向 |

Compatibility.all 中的多个条件必须同时满足。

规则优先级

所有匹配规则都会被评估，最终优先选择：

  1. Priority 更高的规则。
  2. Priority 相同时，效率更高的规则。
  3. 仍相同时，RuleName 字典序更靠前的规则。

MaterialConditionMultiplier 小于 1 表示跨类别或低质量供体的效率惩罚。SkillThresholds 对 Jury 规则当前主要作为最低门槛：配置了 RequiredSkill 时，当前技能必须达到排序后第一档 threshold。maxValue 不用于 Jury 混修上限；混修上限由 OverRepair 和 MCM 另行决定。

当前 CSF 的维修逻辑

当前 Classic Skill System Provider 的设计是：

  • 相同基础物品的正常维修规则不要求 Jury Rigging Perk。
  • 其它跨记录混修通常要求 NVSS_Perk_JuryRigging。
  • 标准远程武器按 Family、Handling 和 Configuration 计算效率。
  • 近战按 Family 和 Handling 计算。
  • Pipe 武器通过 Weapon.Modifier.Pipe 增加跨 Handling 的专门规则，不开放普通武器的全局互修。
  • 护甲按 Material、Region、Grade 计算，Armor.Flag.Ignore 和 Armor.Flag.NoDonor 会被排除。

旧版 TargetKeywords、MatchCategories 和 RankLimits 不是当前 Jury loader 的字段。新规则请使用 AppliesTo、Compatibility、RequiredSkill 和 SkillThresholds。

OverRepair

路径：Repair/OverRepair/<RequiredPlugin>.json

{
  "RequiredPlugin": "Classic Skill System.esp",
  "schemaVersion": 3,
  "module": "Repair.OverRepair",
  "ProviderPriority": 100,
  "OverRepairRules": [
    {
      "RuleName": "Over-Repair Firearms",
      "RequiredSkill": { "Type": "AV", "Plugin": "Classic Skill System.esp", "FormID": "0xFA0" },
      "SkillThresholds": [
        { "threshold": 0.0, "maxValue": 1.0 },
        { "threshold": 50.0, "maxValue": 1.5 },
        { "threshold": 100.0, "maxValue": 2.0 }
      ],
      "AppliesTo": {
        "categories": ["Weapon.Handling.Pistol", "Weapon.Handling.Rifle"]
      }
    }
  ]
}

OverRepair 的阈值会选择“不超过当前技能值的最高 threshold”，并返回对应 maxValue。最终维修上限是：

Jury Rigging:  min(MCM fJuryRepairCap, OverRepair 技能上限)
工作台:        min(MCM fWorkbenchRepairCap, OverRepair 技能上限)

当前工作台不显示维修技能；它只使用这个上限计算。bEnableOverCondition=0 时，OverRepair 和修理包的超额上限会被限制到 100%。

RepairKits

路径：Repair/RepairKits/*.json。当前模板根键是 profiles。

{
  "profiles": [
    {
      "name": "Expert Weapon Repair Kit",
      "formIDs": { "CSF_RepairKit.esp": ["F09"] },
      "canRepairWeapon": true,
      "canRepairArmor": false,
      "baseRepairPoints": 1200,
      "maxConditionLimit": 1.25
    }
  ]
}
  • baseRepairPercent：按目标最大耐久百分比修复。
  • baseRepairPoints：按固定耐久点数修复；出现该字段时使用点数模式。
  • maxConditionLimit：修理包自身的最高目标状况。
  • canRepairWeapon / canRepairArmor：类型限制。
  • formIDs 和 keywords：确定玩家使用的是哪个修理包。

修理包的 maxConditionLimit 仍受 MCM bEnableOverCondition 影响。修理包不能通过 DisplaySkill 获得额外技能资格。
