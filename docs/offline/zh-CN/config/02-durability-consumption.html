耐久消耗模块

基础目录：

Data/F4SE/Plugins/ConditionSystemFramework/Durability/Consumption/

该模块负责“物品如何损耗”，不负责定义物品属于哪个类别。类别由分类模块提供。

Profile 的共同匹配规则

Weapons/*.json、Armors/*.json、Ammos/*.json、Modifiers/*.json 和 Omods/*.json 使用：

{
  "profiles": [
    {
      "name": "My Profile",
      "priority": 100,
      "formIDs": ["MyMod.esp|000123"],
      "keywords": [
        ["Keyword_A", "Keyword_B"]
      ]
    }
  ]
}

formIDs 支持数组，也支持按插件分组的对象写法。keywords 是“外层 OR、内层 AND”：上例表示同时拥有 Keyword_A 和 Keyword_B，或者另一组关键词匹配时命中。

武器和护甲基础 Profile 的匹配顺序是：

  1. AppliesTo 分类条件。
  2. 精确 FormID。
  3. 关键词 AND 组。
  4. 默认 Profile。

带 AppliesTo 的 Profile 按 priority 从高到低排序；同一类型的 FormID 和关键词 profile 也应使用明确 priority 和文件名，避免多条规则含糊匹配。

武器基础 Profile

路径：Durability/Consumption/Weapons/*.json

字段：

| 字段 | 作用 | |---|---| | name | 日志和诊断名称 | | priority | Profile 排序优先级 | | maxDurability | 基础最大耐久点数 | | degradeRate | 每次有效开火或近战攻击的基础磨损点数 | | canJam | 是否允许自动故障机制 | | mechanism | auto、ballistic、energy、overheat、none | | isExcluded | 跳过该 Profile 命中物品的耐久损耗路径；不是全链路排除 | | AppliesTo | 分类匹配条件 |

mechanism: auto 会根据武器和弹药自动判断卡壳、能量故障或过热。显式 none 会关闭该武器的故障机制；显式 overheat 会把它交给过热系统。

当前默认文件 VanillaWeapons.json 用 Handling 选择基础 Profile，再由 CategoryModifiers 对 Family 和 Configuration 做倍率调整。

护甲基础 Profile

路径：Durability/Consumption/Armors/*.json

字段：

| 字段 | 作用 | |---|---| | maxDurability | 基础最大耐久点数 | | useFlatDegrade | 是否改用每次命中固定磨损 | | degradeRate | 固定磨损值，或特殊 Profile 的基础值 | | isExcluded | 跳过该 Profile 命中护甲的耐久损耗路径；不是全链路排除 | | keywords | 基础 ARMO Keyword AND 组 | | AppliesTo | Material、Region、Grade 等分类条件 |

普通护甲通常用 Material Profile 提供最大耐久。Region 和 Grade 由 CategoryModifiers 叠加。Heavy_Power_Armor_Plating 只是特殊 Profile 示例；动力甲核心域仍由分类模块分流。

弹药 Profile

路径：Durability/Consumption/Ammos/*.json

{
  "profiles": [
    {
      "name": "Armor Piercing",
      "weaponWearMult": 1.5,
      "armorDamageMult": 2.0,
      "formIDs": ["MyAmmo.esp|000123"]
    }
  ]
}
  • weaponWearMult 乘在武器基础磨损上。
  • armorDamageMult 乘在攻击对护甲耐久造成的冲击上。
  • 弹药匹配使用 FormID 或关键词，不参与武器分类，因此“弹药属于能量类”不会自动把普通手枪变成过热武器。

CategoryModifiers

路径：Durability/Consumption/CategoryModifiers/*.json

文件根键是 modifiers。所有匹配的 modifier 都会应用：

maxDurability = maxDurability * maxDurabilityMult
degradeRate   = degradeRate * degradeMult + degradeRateFlat

其中 maxDurabilityMult 和 degradeMult 累乘，degradeRateFlat 累加。Domain 可以是 Weapon、Armor 或 Any；AppliesTo 使用 all、any、none。

当前 VanillaCategoryModifiers.json 通过 Weapon Family、Weapon Configuration、Armor Grade 和 Armor Region 调整规模和磨损。

OMOD 与传奇修正

路径：

Durability/Consumption/Omods/*.json
Durability/Consumption/Modifiers/*.json

OMOD profile 字段：

  • degradeMult：已安装 OMOD 的磨损倍率，所有已安装 OMOD 累乘。
  • degradeRateFlat：固定磨损值，所有已安装 OMOD 累加。
  • maxDurabilityMult：最大耐久倍率，所有已安装 OMOD 累乘。
  • immuneToJam：任意匹配的 OMOD 为真时，故障免疫为真。

传奇 ModifierProfile 使用相同的 degradeMult 和 immuneToJam，但来自传奇修饰器而不是普通 OMOD。

SkillModifiers

路径：Durability/Consumption/SkillModifiers/*.json

技能耐久修正不会授予维修资格，只影响耐久消耗：

{
  "modifiers": [
    {
      "name": "BuiltToDestroy",
      "Domain": "Weapon",
      "RequiredSkill": {
        "Type": "Perk",
        "Plugin": "Classic Skill System.esp",
        "FormID": "0xD166",
        "MinRank": 1
      },
      "SkillThresholds": [
        {
          "threshold": 1.0,
          "wearMultiplier": 1.15,
          "wearRateFlat": 0.0
        }
      ],
      "AppliesTo": { "all": ["weapon"] }
    }
  ]
}

运行时会为每条匹配规则选择“不超过当前技能值的最高 threshold”，然后把所有规则的 wearMultiplier 累乘、wearRateFlat 累加。当前 Classic Skill System 配置因此可以实现 Built to Destroy 的 +15% 武器磨损，而暴击部分仍由技能系统自身处理。

武器磨损总流程

有效磨损大致按以下顺序计算：

基础 degradeRate
  * 传奇/OMOD degradeMult
  * 弹药 weaponWearMult
  * SkillModifiers wearMultiplier
  + OMOD degradeRateFlat
  + SkillModifiers wearRateFlat
  * MCM fWeaponWearMultiplier
  * 过热状态倍率（如果当前已过热）

护甲损耗在伤害公式得到基础耐久损耗后，再套用 OMOD、技能和 MCM 的护甲磨损倍率。

关于 isExcluded

WeaponProfile 和 ArmorProfile 支持 isExcluded: true 以及精确 formIDs。当前源码会用它跳过相应的耐久消耗和部分故障/战利品处理路径；它不是分类标记，也不会替代 Weapon.Flag.Ignore 或 Armor.Flag.Ignore。

如果需求是“完全离开 CSF”，包括不显示耐久 UI、不参与维修目标/供体，应使用分类模块的 Ignore FLST。若只是让某个物品不损耗，才适合用 isExcluded profile。
