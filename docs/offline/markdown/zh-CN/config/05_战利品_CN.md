# 战利品模块

运行时目录：

```text
Data/F4SE/Plugins/ConditionSystemFramework/Loot/
```

当前活动子模块是 `Loot/ConditionBonus/`。`Loot/InitialCondition/` 目前没有活动 JSON，初始耐久的随机区间由 MCM 控制。

## Provider 选择

`Loot/ConditionBonus/` 每次只选择一个 Provider。文件必须命名为：

```text
<RequiredPlugin>.json
```

插件未加载时跳过该 Provider。当前 `Loot/ProviderSelection.json` 使用 `PluginLoadOrderFirst`：先比较 `RequiredPlugin` 的加载顺序，再比较 `ProviderPriority`。

## ConditionBonus

当前文件 `Loot/ConditionBonus/Fallout4.esm.json` 的结构：

```jsonc
{
  "LootBonusRule": {
    "GlobalCap": 2.0,
    "RequiredSkill": {
      "Type": "AV",
      "Plugin": "Fallout4.esm",
      "FormID": "0x000002C8",
      "ScaleFactor": 100.0
    },
    "Tiers": [
      {
        "minLevel": 5.0,
        "hitChance": 2.0,
        "bonusMin": 0.05,
        "bonusMax": 0.15
      }
    ]
  },
  "RequiredPlugin": "Fallout4.esm",
  "ProviderPriority": 0,
  "schemaVersion": 1,
  "module": "Loot.ConditionBonus"
}
```

字段：

| 字段 | 作用 |
|---|---|
| `GlobalCap` | 加成后的全局最高状况倍数，例如 `2.0` 表示最多 200% |
| `RequiredSkill` | 读取玩家技能或属性 |
| `minLevel` | 该档位的最低技能值 |
| `hitChance` | 触发本档位的百分比概率，范围按 0 到 100 处理 |
| `bonusMin` / `bonusMax` | 触发后随机增加的状况比例 |

运行时会使用当前技能值可达到的最高 `minLevel` 档位。当前数组应按 `minLevel` 从低到高排列，最后一个满足条件的档位是生效档位。

流程是：

1. 物品本身必须由 CSF 管理耐久。
2. 读取 `RequiredSkill`。
3. 选择技能达到的最高档位。
4. 先按 `hitChance` 投骰。
5. 成功后在 `bonusMin` 到 `bonusMax` 之间随机增加状况。
6. 最终结果受 `GlobalCap` 和 MCM `bEnableOverCondition` 限制。

该模块只影响新获得物品的初始状况，不影响已有物品的维修效率和战斗磨损。

## 初始状况与 MCM

当 `bRandomLootDurability=1` 时：

- 武器在 `fWeaponLootDurabilityMin` 和 `fWeaponLootDurabilityMax` 之间随机。
- 普通护甲在 `fArmorLootDurabilityMin` 和 `fArmorLootDurabilityMax` 之间随机。
- ConditionBonus 在随机结果上追加技能奖励。

`LootBonus_Perk_Example.json.disabled` 不是活动配置，扩展名仍为 `.disabled` 时不会被 loader 读取。
