# 分类模块

运行时目录：

```text
Data/F4SE/Plugins/ConditionSystemFramework/Classifications/
```

分类模块只回答“这个物品具有什么分类事实”。耐久、维修和故障模块通过这些分类决定自己的规则。分类文件不会直接修改 ESP，也不会直接改变物品耐久。

## Provider 类型

当前使用三类分类 Provider：

| Schema | `module` | 用途 |
|---|---|---|
| 3 | `weaponClassifications` | 武器 Family、Handling、Configuration、Flag |
| 3 | `armorClassifications` | 普通护甲 Material、Region、Grade、Flag，以及动力甲域 |
| 2 | `classifications` | 兼容精确 FormID、关键词和实例条件的通用分类规则 |

普通分类的核心数据来自插件中的 FLST。`CSF_Weapons.json`、`CSF_Armor_Concepts.json` 和排除文件使用的 FLST 都位于 CSF 或桥接插件中。

## 武器分类组

| 分类组 | 解析方式 | 当前用途 |
|---|---|---|
| `Weapon.Family` | 可共存 | Ballistic、Energy、Launcher、Melee、Unarmed、Electromagnetic、Gamma、Alien |
| `Weapon.Handling` | 互斥 | Pistol、Rifle、Heavy、Melee1H、Melee2H、Unarmed |
| `Weapon.Configuration` | 可选互斥 | Shotgun、Sniper；也可以为空 |
| `Weapon.Flag` | 可共存 | `Weapon.Flag.Ignore` 等排除/标记 |

一个武器可以同时属于多个 Family，例如镭步枪可能同时命中 Ballistic 和 Gamma。Handling 是主体形态，只保留一个最终结果；相同强度的互斥冲突会返回 Unknown。Configuration 可以没有结果。

当前实例分类不仅检查基础 WEAP，也检查当前物品已经安装的 OMOD。基础 WEAP 的 Keyword 和当前实例新增的有效 Keyword 使用不同上下文优先级，已安装 OMOD 的 Attach Point 角色可以改变 Handling、Family 或 Configuration。

### Pipe 武器

`Integrations/CSF_Pipe_Weapons.json` 使用 Schema 2 的通用分类规则，检查基础 WEAP 或实例最终有效 Keyword 中的 `dn_weap_Pipe`，命中后追加：

```text
Weapon.Modifier.Pipe
```

这是修理用的附加标记，不会覆盖 `Weapon.Family` 或 `Weapon.Handling`。当前 Jury Rigging 用它把 Pipe 手枪、Pipe 步枪和 Pipe 霰弹枪放入额外的宽松跨 Handling 修理规则。

## 护甲分类组

| 分类组 | 解析方式 | 当前用途 |
|---|---|---|
| `Equipment.Domain` | 互斥 | `Equipment.Domain.PowerArmor` 命中后退出普通护甲耐久流程 |
| `Armor.Material` | 互斥 | Textile、Flexible、Rigid、Scrap |
| `Armor.Region` | 互斥 | Torso、Limbs、Head、Face、Accessory |
| `Armor.Grade` | 可选互斥 | A、B、C；主要由 Size 角色和实例 OMOD决定 |
| `Armor.Flag` | 可共存 | `Armor.Flag.Ignore` |

Material 和 Region 默认从基础 ARMO 判断。Region 没有命中时，C++ 会使用 BOD2 兜底。Size 角色可以通过当前实例 OMOD 改变 Grade；Tier、Lining、Weave、Paint、Legendary 和 Misc 属于已识别的实例角色，但不参与三层核心分类，它们留给独立耐久 modifier 使用。

命中 `Equipment.Domain.PowerArmor` 后，CSF 不把该物品当作普通护甲处理，保留原版动力甲耐久路径。

## 完整排除

### 武器

`Weapon.Flag.Ignore` 的 FLST 支持 KYWD、WEAP 和嵌套 FLST。命中后，CSF 将该武器标记为不进入耐久系统，也不会作为维修目标或维修供体。

### 普通护甲

`Armor.Flag.Ignore` 的 FLST 支持 KYWD、ARMO 和嵌套 FLST。它同样会让护甲离开 CSF 耐久和维修流程。

精确排除单个 FormID 的推荐步骤是：

1. 在自己的补丁插件中建立一个 FLST。
2. 把目标 WEAP 或 ARMO 直接加入该 FLST。
3. 在分类 Provider 中把该 FLST 注册到相应的 Ignore 分类。
4. 在 `requires` 中声明自己的补丁插件，确保它未加载时不会产生错误分类。

示例：

```jsonc
{
  "schemaVersion": 3,
  "module": "armorClassifications",
  "domain": "armor",
  "provider": "My Armor Exclusions",
  "requires": ["My Armor Patch.esp"],
  "ProviderPriority": 100,
  "groups": { "Armor.Flag": { "mode": "coexisting" } },
  "classifications": {
    "Armor.Flag.Ignore": [
      {
        "list": "My Armor Patch.esp|0x000800",
        "contexts": ["base"],
        "listPriority": 100
      }
    ]
  }
}
```

`formIDs` 直接数组主要属于耐久 profile 的精确匹配字段；分类 Schema 3 的精确物品排除通过 FLST 完成。不要把普通护甲的直接 JSON FormID 写进 Schema 3 的 `classifications`，因为该 Schema 的 `list` 必须解析为 FLST。

## 自定义分类 Provider

武器 Schema 3 的基本结构如下：

```jsonc
{
  "schemaVersion": 3,
  "module": "weaponClassifications",
  "domain": "weapon",
  "provider": "My Weapon Provider",
  "requires": ["My Weapon Patch.esp"],
  "ProviderPriority": 100,
  "groups": {
    "Weapon.Family": { "mode": "coexisting" }
  },
  "classifications": {
    "Weapon.Family.Ballistic": [
      {
        "list": "My Weapon Patch.esp|0x000801",
        "contexts": ["base", "instance"],
        "listPriority": 100
      }
    ]
  }
}
```

Schema 2 的通用规则适合需要直接匹配 FormID 或 Keyword 的扩展：

```jsonc
{
  "schemaVersion": 2,
  "module": "classifications",
  "domain": "weapon",
  "provider": "My Exact Weapon Rules",
  "requires": ["My Weapon Patch.esp"],
  "sourceTier": 200,
  "categories": [
    {
      "id": "Weapon.Modifier.MyGroup",
      "domain": "weapon",
      "match": {
        "combine": "any",
        "base": {
          "forms": ["My Weapon Patch.esp|000812"],
          "keywordsAny": ["My_Keyword"]
        }
      }
    }
  ]
}
```

Schema 2 支持 `forms`、`formLists`、`keywordsAny`、`keywordsAll`、BOD2 条件和实例 OMOD/Keyword 条件。它更适合扩展标记；核心武器分类和护甲分类应优先使用当前 Schema 3。

## 依赖与排错

- `requires` 中任何插件未加载，整个 Provider 会跳过。
- `Classifications/ProviderSelection.json` 只控制冲突排序，不会把缺依赖的 Provider 强行加载。
- 不要直接使用 `WeaponTypeUnarmed` 作为武器排除条件；正常拳套类武器也可能携带该 Keyword。
- 创建分类 FLST 后，必须确认其 FormID 是 FLST，而不是 KYWD、WEAP 或 ARMO 本身。
- 日志关键字：`[Classification]`、`[ArmorConcepts]`。
